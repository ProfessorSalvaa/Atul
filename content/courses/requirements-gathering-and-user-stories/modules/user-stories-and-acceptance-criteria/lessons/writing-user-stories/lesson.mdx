This lesson is part of **User Stories and Acceptance Criteria** in _Requirements Gathering and User Stories_. By the end, you should be able to put the following into practice:

- The standard format — 'As a [user], I want [goal], so that [benefit]' — forces you to state who benefits and why, not just what to build, which keeps the team focused on the actual value
- A story should be small enough to complete within a sprint — a story that's too large ('as a user, I want a dashboard') should be split into smaller, independently valuable stories
- INVEST is a useful checklist for a good story: Independent, Negotiable, Valuable, Estimable, Small, Testable

```text
As a returning customer, I want my saved payment method pre-filled at checkout, so that I can complete a purchase faster.

Acceptance criteria:
- Saved card shows as pre-selected if one exists
- User can still choose a different payment method
- No saved card is shown if none exists (no error state)
```
